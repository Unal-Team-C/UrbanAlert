2. Arquitectura (Clean / Hexagonal)

Las dependencias solo apuntan hacia adentro. El dominio no conoce Spring ni JPA. La infraestructura implementa los puertos definidos por el dominio.

API Layer — com.urbanalert.users.api

UserController · HomeController · GlobalExceptionHandler
DTOs (CreateUserRequest, UpdateUserRequest, UpdateUserRoleRequest, UserResponse) · UserApiMapper

↓ llama a puertos de entrada ↓

Application Layer — com.urbanalert.users.application

Puertos de entrada: CreateUserUseCase · GetUsersUseCase · GetUserByIdUseCase · UpdateUserUseCase · UpdateUserRoleUseCase · DeleteUserUseCase
Servicio: UserService (implementa todos los use cases, transaccional, reglas de negocio)

↓ usa entidades de dominio ↓

Domain Layer (núcleo) — com.urbanalert.users.domain

Entidad: User (UUID v7, validaciones en constructor, sin anotaciones de framework)
Enum: Role (USER, ADMIN)
Puerto de salida: UserRepository (interfaz)
Excepciones: UserNotFoundException · DuplicateEmailException · LastAdminException

↓ implementado por ↓

Infrastructure Layer — com.urbanalert.users.infrastructure

UserJpaEntity (@Entity, Lombok) · UserJpaRepository (JpaRepository) · UserRepositoryAdapter (implementa UserRepository)
UserPersistenceMapper · DataInitializer (@Profile("local"), seed idempotente)

Regla clave del diseño

La entidad JPA (UserJpaEntity) está completamente separada de la entidad de dominio (User). El mapper de persistencia (UserPersistenceMapper) traduce entre ambas. Esto garantiza que cambios en la base de datos no afecten el dominio y viceversa.

6. Reglas de negocio

Email único (BR-001)

No puede existir dos usuarios con el mismo email. Se valida en crear y en actualizar (ignorando el propio usuario). El índice uix_users_email en PostgreSQL actúa como segunda línea de defensa.

Último admin protegido (BR-002)

Si solo queda 1 usuario con rol ADMIN, no se puede eliminar ni cambiar su rol a USER. Se lanza LastAdminException → 409. El sistema siempre debe tener al menos un admin.

UUID v7 (BR-003)

Los IDs se generan con java-uuid-generator (Generators.timeBasedEpochGenerator()). UUID v7 es ordenable cronológicamente — compatible con el Guid.CreateVersion7() usado en los microservicios .NET del mismo monorepo.

Role por defecto (BR-004)

Si se crea un usuario sin especificar role, se asigna USER automáticamente. En PUT el rol es obligatorio (no hay default en actualización).

8. Esquema de base de datos

-- V1__create_users_table.sql
CREATE TABLE users (
    id    UUID         NOT NULL,
    name  VARCHAR(200) NOT NULL,
    email VARCHAR(300) NOT NULL,
    role  VARCHAR(20)  NOT NULL,   -- valores: 'USER' | 'ADMIN'
    CONSTRAINT pk_users PRIMARY KEY (id)
);

CREATE UNIQUE INDEX uix_users_email ON users (email);

No hay created_at ni updated_at por ahora — el microservicio de Usuarios no gestiona auditoría propia (hay un microservicio separado UrbanAlert.Auditoria en el monorepo para eso).

14. Cómo ejecutar

Opción A — IntelliJ (perfil local)

  1. File → Open → seleccionar build.gradle.kts → "Open as Project"
  2. Esperar sync de Gradle (panel derecho)
  3. Edit Configurations → VM options: -Dspring.profiles.active=local
  4. Run UsersApplication
  5. Acceder a http://localhost:8080/swagger-ui.html

Opción B — Terminal (perfil docker)

cd backend/UrbanAlert.Usuarios/deploy/docker

# Levantar PostgreSQL + servicio
docker compose up -d

# Ver logs
docker compose logs -f users-service

# Servicio en:
http://localhost:8081/swagger-ui.html

# Bajar
docker compose down
